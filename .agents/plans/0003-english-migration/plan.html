Migration of the code and the documentation to English

gamelibrarymanager · claude/migrate-english-asd-ste100-bt3rux · 2026-08-15 · size: L

This plan is written after the work, not before it. It records what was done, the decisions that the work made, and the two consequences that reach outside the repository. The plan documents 0001 and 0002 keep the decisions of the product; this one keeps only the decisions of the migration.

Goal

All of the project is in English. The code — comments, doc comments, identifiers, user-facing strings, SQL comments, CSS tokens and class names — reads as English. The documentation is in English and obeys ASD-STE100: short sentences, the active voice, one idea in each sentence and simple words. No behaviour of the application changes, except the language that the user reads and two locale decisions that go with it.

Status

The plan is done: the four phases (commits 186d8b6, a39f13c, 3f58870; phase 1 wrote no code). Green: cargo fmt --all --check, cargo clippy --all-targets --workspace -- -D warnings, cargo test --workspace (125), bunx tsc --noEmit, bun run lint, bun test (70) and bun run build.

Not run in this session: bun run visual. Chromium starts in the container and gives no answer, thus the harness waits. The harness does typecheck — tsconfig.json includes test — and each CSS selector that it uses was compared against src/styles.css and the components; all of them resolve. The check still needs one run on a real desktop. AGENTS.md already lists it as one of the two checks that CI cannot make.

Scope

In

  • The six crates, src-tauri, the React interface, src/styles.css and the SQL migrations.
  • All of the tests: the Rust suites, the inline #[cfg(test)] modules, the frontend tests and the visual harness.
  • README.md, NOTICE, AGENTS.md, the fourteen conventions of docs/ and the job names of .github/workflows/ci.yml.
  • File names: source files, test files, fixtures, migrations and documents whose name was in Spanish.

Out

  • .agents/plans/0001-* and 0002-*. They record closed decisions with the alternatives refused, and AGENTS.md says that nobody discusses them again. To translate them would rewrite the record of decisions that this migration did not make.
  • The commit history. The old messages stay as they were written.
  • The names of the real games in the fixtures. Disco Elysium and The Witcher 3 are the names of products, not text of this project.
  • Any change of behaviour that the language does not make necessary.

Current state

The project was written in Spanish and had started to move to English without a plan. Six files were already English — connectors/src/epic/, commands/epic.rs, storage/tests/connector_state.rs, docs/connectors/switch-per-connector.md, docs/tauri/scripts-in-a-login-window.md and the migrations 0006 and 0007 — and their neighbours were not. Some documents carried an English title and a Spanish body. docs/documentation-guidelines.md made the Spanish a rule: «En español, como el resto del proyecto».

Decisions

QuestionDecisionWhy / refused
What is "the code" and what is "the tests" in the requested order?Phase 2 migrates the source and carries the renames into the tests only where a test would stop to compile. Phase 3 migrates the tests themselves.The requested order asks for a validation between the two. A test file that does not compile makes that validation worth nothing, and the failures that stay are then exactly the ones expected: the assertions on hardcoded Spanish text. Refused to leave the tests completely untouched: tsc and cargo would have failed on missing symbols and would have hidden a real regression
Do the inline #[cfg(test)] modules count as code or as tests?As tests: phase 2 translated the code around them, phase 3 translated them.They are tests, and the rule of the phase must not depend on the file that holds them. Refused to migrate them with their file: the second validation would then have had failures that nobody predicted
Does ASD-STE100 also apply to the code comments?Strictly in docs/, README.md, NOTICE and AGENTS.md. In the code, plain and short English in the register that the already-English files used.The request names the documentation. The comments that were already English (connectors/src/epic/mod.rs) set a register, and a second register in the same file reads as two authors. Refused to apply STE to the code: it would have rewritten the six files that nobody asked to change
Do the SQL comments of the migrations move?Yes, in 0001 to 0005.0006 and 0007 were already English, thus the project had already accepted the cost. To stop here would leave the schema as the only part in Spanish. Consequence: the sqlx checksum of those five migrations changes, and a database made before this branch fails MIGRATOR.run with a version mismatch. There is no tag and no release, and the tests use an in-memory database
Do the migration files change their name?Yes: 0004_match_candidate_ficha → 0004_match_candidate_record, 0005_origen_visible → 0005_visible_origin.sqlx examines the checksum, not the description, thus the name costs nothing more than the checksum that the comments already changed. Refused to keep the Spanish names: they were the last Spanish in migrations/
What language do the sort and the money use?localeCompare(…, "en") and Intl.NumberFormat("en-GB").The code held these two values as "the language of the application", and the comment said so. The language changed, thus they change with it. Consequence: a price now reads 15.99 and not 15,99. Refused to keep "es"/"es-ES": an English interface that writes Spanish numbers is the defect that the comment tried to prevent
What does the CSS class .resumen become?.synopsis.The direct translation, .summary, already exists in App.tsx on the count of records, and it has no rule in the sheet. To use the name again would give that paragraph the styles of the game synopsis. Refused also to rename the other class: it would have made two changes where one was sufficient
Which SQL alias replaces puesto in the price query?ordinal.rank is the name of a window function of SQLite, and an alias with that name reads as a call. Refused rank and position: the first is confusing and the second is also a keyword of other engines
What happens to the invented text of the fixtures?It moves: SECRETO_QUE_APORTA_EL_USUARIO → SECRET_THAT_THE_USER_SUPPLIES, PAGINA_2 → PAGE_2, and the three fixture files with a Spanish name.They are text of this project, not answers of a store: the recorded answers keep the shape that the store gives, and only the invented values change. Refused to keep them: a test that reads TOKEN_DE_REFRESCO_ROTADO makes the reader change language in the middle of a line
Are the plan documents translated?No.AGENTS.md says that the closed decisions are not discussed again. A translation rewrites them. If the project wants them in English one day, that is a decision of the project and it needs its own plan
Does the documentation rule change?Yes: docs/documentation-guidelines.md now demands English and ASD-STE100.The rule said Spanish. To translate the documents and leave the rule would make the next document Spanish again, and the migration would start to come undone at the first new convention

Plan

Phase 1 — The baseline

Objective: to know that the suite is green before a change, so that each later failure belongs to the migration.

The container had no Tauri system dependencies and cargo test stopped at gdk-sys. apt-get update and the four packages of the CI job corrected that.

Done when: cargo fmt --all --check, cargo clippy --all-targets --workspace -- -D warnings, cargo test --workspace, bunx tsc --noEmit, bun run lint and bun test (70) all pass. They did.

Data & contracts

No table, no column and no command signature changes. What crossed a boundary is text, and these four are the places where a change on one side needs a change on the other:

ContractTwo sides
The stage of SyncProgressRust writes it (sync.rs, identity.rs, prices.rs) and App.tsx shows it with no translation. The six values moved together
The thiserror messagesThe user reads them, and connector_switch.rs and sync.rs assert on part of them. Message and assertion moved together

Risks

RiskWhat it doesWhat was done

Verification

cargo fmt --all --check
cargo clippy --all-targets --workspace -- -D warnings
cargo test --workspace                     # 125 tests, 0 failures
bunx tsc --noEmit && bun run lint && bun test   # 70 tests, 0 failures
bun run build

All of them pass in this branch. Two more, which CI cannot make:

cargo test -p secrets --test keyring_real -- --ignored   # needs secret-service
bun run build && bun run visual                          # needs a Chromium

The first stays #[ignore], as before. The second did not run here.

Unknowns

  • Whether the visual harness passes on a real desktop. The selectors resolve and the file typechecks, but only a run says it.
  • Whether en-GB is the currency format that the project wants. en-US writes the same numbers and a different currency symbol position; the decision was made for the language of the interface and nobody has looked at a screen with dollars.
  • Whether the plan documents 0001 and 0002 stay in Spanish for ever. This plan does not decide that.

Do not

  • Do not translate .agents/plans/0001-* or 0002-*. They hold closed decisions.
  • Do not change the comments of a migration again without a reason. Each change costs the checksum of every database that exists.
  • Do not write a new document in Spanish. docs/documentation-guidelines.md now demands English and ASD-STE100.
  • Do not rename a CSS class in only one of the four places that use it.
  • Do not translate the names of the real games in the fixtures. They are products, not text of this project.
