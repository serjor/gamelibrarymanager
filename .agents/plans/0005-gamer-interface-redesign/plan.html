Decision context

What changes and why it matters

Behavior

Change: Product navigation moves to a rail. Account and provider actions move to a utility panel.

Why it matters: The collection becomes the primary subject. Maintenance actions no longer compete with it.

Mechanism: src/App.tsx:279-456 moves its presentation into components in src/features/shell/.

Visual identity

Change: The interface gets one brand mark, two complete themes, artwork fallbacks, and controlled motion.

Why it matters: A record with no cover still looks intentional. The application no longer looks like a generic form.

Mechanism: src/styles.css:8-97 expands its token system. Local SVG geometry supplies the marks and icons.

Code

Change: New shell and artwork components remove top-level presentation from App.tsx.

Why it matters: App.tsx keeps data orchestration. The new components only show state and send actions.

Mechanism: The implementation follows the feature-directory structure in README.md.

Data and contracts No change

LibraryRow already supplies vertical art, wide art, metadata, stores, play time, status, rating, and notes.

Evidence: src/lib/api.ts:76-104. No phase changes SQLite, Rust commands, or serialized data.

Accessibility

Change: The new shell adds predictable focus, text labels, and a reduced-motion mode.

Why it matters: Visual personality must not remove keyboard use, screen-reader structure, or readable contrast.

Mechanism: The true tables and native dialog remain. Evidence: LibraryTable.tsx:43-51 and GameDetail.tsx:54-64.

Developer workflow

Change: The visual harness gains shell, artwork, setup, theme, and reduced-motion cases.

Why it matters: The shell changes the layout relationships that the current harness measures.

Mechanism: Extend test/visual/harness.ts and test/visual/look.ts:39-530.

Boundaries

Approved scope

In

  • A live-archive identity for the wall, Today, and the game record.
  • A command-deck identity for the table, filters, bulk actions, Wishlist, and Review.
  • A labeled navigation rail and a labeled top navigation at small widths.
  • A native utility dialog for accounts, providers, export, and disconnect actions.
  • A visible activity strip for errors, provider problems, progress, and cancellation.
  • A dark-primary theme and a complete light theme from the system preference.
  • A local brand mark and a complete desktop icon set.
  • Deterministic monograms and token-based patterns for missing artwork.
  • Brief motion and full support for prefers-reduced-motion.
  • The six setup flows, loading, empty, error, and progress states.
  • Functional and visual tests for all changed behavior and layout.

Out

  • Controller input, television mode, and a full-screen mode.
  • Launching, installing, downloading, or patching games.
  • A mobile application or a mobile-specific product flow.
  • A theme marketplace, custom themes, or a persistent theme selector.
  • A density selector or new stored interface preferences.
  • A custom font, remote font, icon package, or interface library.
  • Generated cover art, downloaded filler art, or external design assets.
  • New recommendations, changed Today rules, or new metadata.
  • Changes to matching, prices, connectors, storage, or domain rules.
  • Changes to the closed product structure in plan 0002.

Closed decisions

Do not relitigate

QuestionDecisionReasonRejected alternative
What visual direction applies?Live archive for emotional surfaces. Command deck for operational surfaces.The product must support collection pleasure and dense management.One visual treatment for all screens. It weakens either artwork or comparison.
Does age define a mode?No. The interface serves the task: explore, decide, or manage.Players across age groups share these tasks. Age stereotypes do not describe an interaction requirement.Young, online, and veteran themes. They divide users without a product reason.
Does this change plan 0002?No. The library starts first. Table and wall share state. Today stays separate. One record has two presentations.These structures operate and have broad test coverage.A backlog board, terminal view, or Today as the home screen. Plan 0002 rejected them.
Does the application get controller or television support?No.The application does not launch games. A television shell makes a false launcher promise.A Focus and Manage dual mode. True controller navigation changes the scope to size L.
How does top-level navigation work?A labeled rail changes to labeled top navigation when space is insufficient.Text labels keep context. The table keeps its minimum readable width.Icon-only navigation. It adds learning cost and weak context.
Where do maintenance actions go?A native utility dialog holds accounts, providers, export, and disconnect actions.These actions stay available but do not compete with the collection.The current permanent header. It keeps the administrative hierarchy.
What stays visible outside the dialog?Active progress, cancellation, errors, and provider problems.A hidden error or operation state makes the application appear idle or correct.All status inside the utility dialog. It hides important state.
How do themes work?The system preference selects a dark-primary theme or a complete light theme.The current application already uses prefers-color-scheme. No preference storage is necessary.A dark-only theme or a stored selector. One excludes contexts. The other adds state.
What happens without artwork?A deterministic monogram uses one of four token patterns.The no-IGDB path is a supported product state.Fabricated covers, remote filler art, or plain gray boxes.
What identity mark applies?Three portrait cards converge into one library frame. The mark contains no text or controller.The shape describes store copies that become one record. It stays distinct from a launcher.A gamepad, letter mark, or store logo collage.
Can the work add visual dependencies?No. Use React, CSS, local SVG geometry, and the current Tauri CLI.The required shapes and motion are small. A package adds more code than the feature needs.An icon set, motion library, component kit, or custom font.
How much motion applies?Use brief state transitions. Remove nonessential motion under prefers-reduced-motion.Motion can explain focus and hierarchy. Continuous motion competes with the collection.A static interface or decorative ambient animation.
Does the user select density?No. Use one balanced density.A selector needs preference state and more layout cases.Compact and comfortable modes.
